# Purpose

This document defines the relationships and responsibilities of every major component in the BarelySmash Intelligence Platform.

It is the canonical architectural reference.

```
         │               │                │                │

  ─────────────────────────────────────────────────────────────
                          Foundation
           Shared technical capabilities. No business logic.
```

# Component Categories

The platform recognizes three categories of component beneath JARVIS:

- **Engines** transform domain data into Decision objects.
- **Applications** present intelligence generated by engines.
- **Utility Agents** perform bounded tasks on delegation. They do not
  emit Decision objects and do not own a domain.

Every engine and utility agent JARVIS can route to is declared in the
JARVIS agent registry (`config/agents.yaml` in jarvis-v2). Nothing is
added directly to JARVIS itself. The registry supports two transports:
in-process adapters wrapping peer HTTP services, and MCP stdio servers
launched as child processes. Each entry loads independently; one
agent's failure never blocks the rest.

# Responsibilities

## JARVIS

Mission:

Coordinate specialized intelligence engines and present a unified executive experience.

Responsibilities

- Route requests
- Coordinate engines and utility agents
- Maintain executive context
- Schedule work
- Aggregate decisions
- Present executive briefings

JARVIS never owns domain-specific reasoning.

---

## Atlas

Mission:

Transform operational data into operational decisions.

Responsibilities

- Operational Records
- Events
- Metrics
- Organizational Memory
- Operational Reasoning
- Forecasting

Outputs

Decision objects.

---

## Friday

Mission:

Transform market data into trading decisions.

Responsibilities

- Market Structure
- Risk
- Portfolio Intelligence
- Execution Planning
- Trading Memory
- Forecasting

Outputs

Decision objects.

---

## Muse

Mission:

Transform ideas into structured creative decisions and production-ready creative direction.

Responsibilities

- Creative Briefing
- Storytelling
- Art Direction
- Prompt Construction
- Creative Evaluation
- Typography Planning
- Prepress Reasoning
- Creative Artifact Preparation

Muse does not own executive orchestration, trading intelligence,
hospitality intelligence, storefront presentation, checkout, inventory,
fulfillment, or shared cross-platform infrastructure.

Muse is an independent engine. JARVIS may delegate creative work to Muse
through versioned contracts, but Muse does not depend on JARVIS internals.

Outputs

Decision objects.

---

# Utility Agents

Utility agents extend what JARVIS can do without claiming a domain.
They are delegated bounded tasks, return results, and hold no
platform state. They do not emit Decision objects, and no application
is built on them.

## Sparrow

Mission:

Acquire genuinely-free assets with resolved licensing.

Responsibilities

- Free-asset discovery (public-domain, CC, open datasets, official APIs)
- License resolution
- Attribution construction
- Official-source location
- Licensed-alternative search

Transport

MCP stdio server, registered in the JARVIS agent registry. Tools are
namespaced under `sparrow_`.

Outputs

Assets with license and paste-ready attribution. Not Decision objects.

# Applications

Applications present intelligence generated by engines.

Applications never generate intelligence.

Current applications

- RestaurantOS
- BarelyTrade

Future applications

- WineryOS
- HotelOS
- RetailOS

---

# Shared Infrastructure

Shared technical capabilities belong in Foundation.

Examples

- Configuration
- Logging
- Notifications
- Scheduling
- Storage
- LLM adapters
- Authentication
- External search APIs (e.g. Tavily)

Foundation never owns business logic.

---

# Core Principle

> Engines produce decisions.

> Applications present decisions.

> Utility agents perform tasks.

> JARVIS coordinates all of it.
